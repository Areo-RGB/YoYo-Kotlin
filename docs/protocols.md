# Fitness test protocols

The protocol reference is maintained here rather than as a tab in the app. The authoritative executable schedules remain in [`domain/Protocol.kt`](../app/src/main/java/com/example/yoyo/domain/Protocol.kt) (see `protocols`, `createYoYoShuttles`, and `createBeepShuttles`). This document describes the current implementation, not an independently certified test standard.

## Supported tests

| Test | Schedule definition | Audio timing adjustment |
| --- | --- | --- |
| Yo-Yo Intermittent Recovery Level 1 (IR1) | 20 m shuttle runs with recovery; starts at level 5 / 10.0 km/h | run scale 0.9992; recovery 10,018 ms |
| Yo-Yo Intermittent Recovery Level 2 (IR2) | 20 m shuttle runs with recovery; starts at level 11 / 13.0 km/h | run scale 0.9996; recovery 10,009 ms |
| Beep Test | Progressive continuous 20 m shuttles | audio lead 10,215 ms |

The Yo-Yo schedules are expanded from level, speed (km/h), and shuttle-count groups in `protocols`. IR1 includes initial groups at levels 5, 9, 11, 12 and 13, followed by levels 14–23 in 0.5 km/h increments with eight events each. IR2 uses levels 11, 15, 17–26, with eight events at each level from 20 onward. Beep Test shuttles are generated by `createBeepShuttles`.

## Reading the former protocol table

The removed in-app **Protocol table** showed only the first 24 scheduled shuttle events for the currently selected test. Its columns were:

- **#**: scheduled shuttle number
- **LEVEL**: displayed level / stage for that shuttle
- **SPEED**: target speed in km/h
- **DISTANCE**: cumulative distance in metres

For the full schedule, consult the shuttle-building functions and `protocolFor(TestType)` in `domain/Protocol.kt`. The values are calculated from the same data that drives the live test; documenting this avoids maintaining a separate, possibly outdated table.

## During a test

Select the test type in the app's protocol switcher. The selected schedule controls the live clock, runs, recovery periods, shuttle progress, distance and results. Bundled audio is used for cues, with the per-test calibration values above. Muting the audio does not stop the protocol clock. The test supports pause/resume and completion, while athlete actions record misses, warnings, and elimination.

**Important:** Keep the in-code definitions and bundled audio aligned when changing timings. After updating schedules, run `./gradlew testDebugUnitTest lintDebug`. `ProtocolTest` checks shuttle totals, runtime behaviour, and alignment with the beeps measured in the recordings.
